
# Proposal Notes Template

## Structure

The proposal-notes.md note is the plan artifact for a proposal. It should be
written to be useful *during* the proposal submission process — a reference
document the user can keep open while filling out the Upwork form.

---

```markdown
# Proposal Notes

[[content|Original job posting]]

## Key Points

**Positioning:** [One or two sentences: what is the core argument for fit,
and what is the differentiator that sets this candidacy apart from generic
PHP/API applicants.]

**What to lead with:** [The specific capability or project type that most
directly maps to the posting's core need.]

**Tone:** [Brief characterisation: technical peer / capable contractor /
specialist. Any specific register notes.]

**Rate:** [If pricing below experience level — why, and how it's contextualised
in the cover letter. If a client asks directly, what's the honest framing.]

**Budget/scope anomaly:** [If present — describe the anomaly and the strategy
for addressing it (e.g. discovery milestone).]

**Milestone strategy:** [If applicable — milestone title, what it delivers,
why it's the right first step, and where the framing belongs (terms field,
not cover letter).]

### Suggested milestone field wording

[Paste the exact text to put in Upwork's milestone/terms field, if applicable.]

## Relevant Projects

[For each relevant project: name, one-line description, then bullet points
of specific capabilities demonstrated that map to the posting's requirements.
Draw from KB research. Be specific — file names, patterns, and line counts
are more convincing than generalities.]

## Form and Content of Cover Letter

**Shape:** [Describe the paragraph structure and what each paragraph does.]

### Cover Letter Draft

---

[Draft in flowing prose, no headers or bullets. Written to the rules in
cover-letter-guide.md.]

---
```

## Notes on Use

- The draft is a starting point, not a final product. The user will refine it
  before submitting.
- When updating the note after iteration (rate line added, milestone strategy
  added, etc.), always read the current note first and update in place rather
  than rewriting from scratch.
- The `[[content|Original job posting]]` link should always be the first line
  after the title — it provides one-click access to the source material.
